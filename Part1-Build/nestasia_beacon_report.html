Friction Point Analysis

1. Trending = sold out, with no recovery path

84.8% of Nestasia's own hand-curated "What's Trending" collection (1064 of 1254 products, per the store's live availability facet) is out of stock. There is no back-in-stock alert on these product pages — a shopper who lands on a trending product Nestasia is actively promoting has a coin-flip chance of hitting a dead end with no way to be notified.

2. Discounted + sold-out variants compound

Among the deep-dive sample, products carrying both a live discount and a partial sellout rate show the classic "hot item" pattern — price cut drove a burst of demand that outran stock on specific variants (size/color), while other variants of the same product sit fully available and undiscounted. That's inventory-allocation intelligence Nestasia's team can't see from the storefront today.

3. Gifting intent has no dedicated capture mechanism

Products cross-linked into occasion-specific gifting collections (Housewarming, Wedding, Anniversary, etc. — see facet weights) carry seasonal, date-sensitive intent. A wishlist without ESP integration can't remind a shopper before Diwali or a wedding date; that intent simply expires unrecorded.

4. Multi-collection membership is an unused prioritization signal

9 products in this dataset appear in more than one target collection simultaneously (e.g. trending AND on a discount collection) — a stronger demand signal than either collection alone, and one the merchant dashboard has no way to surface today without a tool like Beacon.

Engineering Approach & Effort

This diagnostic was built and run end-to-end against the live storefront, not against sample or cached data. Two blockers surfaced during implementation and both required a real engineering pivot, not a workaround:
  • Cloudflare bot management. Plain HTTP requests (curl, Python requests, any standard browser User-Agent header) return HTTP 403 "Just a moment..." on the oembed endpoint, every collection page, and every product page — verified directly before any scraping logic was written. The fetch layer was rebuilt on headless Chromium via Playwright, which executes Cloudflare's JS challenge like a real browser and clears it reliably after an ~8s settle window per navigation.
  • Broken oembed pagination. The collection oembed endpoint's page query parameter is a no-op on this store — page=1, page=2, page=100, and no parameter at all were fetched and diffed product-for-product, and all four returned the identical first 50 products. There is no way to page past 50 products per collection from outside the store today. This caps every collection in this dataset at ~50 products rather than its true catalog size (e.g. "What's Trending" holds 1,254 products per its own availability facet, but only 50 were retrievable via oembed) — disclosed in the Methodology section below rather than absorbed silently into the totals.
Everything reported above — the 84.8% trending-collection stockout rate, the availability facet counts, the occasion-tag weights, the per-product review histograms — was read live off nestasia.in during this run, with no synthetic or placeholder data anywhere in the pipeline.

Backend & Data Access Needed From Nestasia

The signals above are everything reconstructable from public storefront pages alone. A production Beacon integration would need direct access to close the gaps this diagnostic had to work around:
  • Shopify Admin API access (or a merchant-side data feed) — to read the full product catalog, true inventory_quantity per variant, and product_type/tags directly, instead of inferring stock state from a public storefront facet and capping catalog depth at 50 products per collection via oembed.
  • Real-time inventory webhooks (Shopify's inventory_levels/update topic or equivalent) — to trigger back-in-stock notifications the moment stock returns, rather than polling a Cloudflare-gated storefront.
  • Order and conversion history per product/variant — the "estimated demand value" figure in this report is a stock × price proxy; actual add-to-cart, checkout-start, and conversion data would let intent-risk scoring reflect real lost revenue instead of a directional estimate.
  • Wishlist interaction events — Nestasia's current heart-icon wishlist writes to localStorage only, with no server-side record. Replacing it with Swym Wishlist Plus (or instrumenting the existing UI to emit events) is what turns "shopper clicked a heart icon" into a contactable, ESP-ready record.
  • Customer identity / email opt-in linkage — to route captured intent (sold-out variant, wishlist add, gift-collection browse) into re-engagement flows; currently there's no session-to-contact bridge on the storefront.
  • An allowlisted integration path around the Cloudflare bot rules — either an IP/agent allowlist for a lightweight polling client, or (preferably) API-based access that removes the need to render pages through a browser at all. This determines whether a production version of this pipeline runs as a scraper or as a proper integration.

Methodology & Signal Labels

Directly measured (from live storefront data, this run): variant sellout rate, price, review count & rating, discount depth, collection membership, occasion facet counts, trending-collection availability split.
Proxies (stand-ins for data Beacon would get directly via pixel/API in a real integration): "image version timestamp" as a recency signal, "gift occasion links" as a gifting-intent signal, "estimated demand value" as a revenue-risk signal, and the category breakdown (grouped by collection, not true product type).
Known coverage limits, disclosed rather than hidden: the oembed endpoint's page parameter does not paginate on this store (verified: page=1/2/100 all return the same 50 products), so each collection contributes at most ~50 products to this dataset, not its full catalog depth. Product-page deep-dive fields (inventory count, discount %, reviews) were only fetched for the top 25 products by raw sellout rate, to keep this run's wall-clock time reasonable against Cloudflare's per-request JS-challenge overhead.
